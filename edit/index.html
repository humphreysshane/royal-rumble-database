This page talks to GitHub's API directly from your browser — nothing goes through any third party, and your token is kept only in this browser's local storage.

How do I get a token, and what scope does it need?
1. Go to github.com/settings/personal-access-tokens/new (fine-grained tokens — these can be locked to one repo, which classic tokens can't).
2. Under Resource owner pick your account, and under Repository access choose Only select repositories → royal-rumble-database.
3. Under Repository permissions set Contents to Read and write and Pull requests to Read and write (Metadata read-only is added automatically).
4. Generate it and paste it above. It never leaves your browser except in requests to api.github.com.

Save as a pull request

Nothing is written to main directly — this opens a PR from a new branch, same as any other change to the database. Run scripts/validate_integrity.py before merging it, same as usual.

Edits are saved as a normal GitHub pull request — reviewed and merged the same way as any change from a person or another tool. Duplicate primary-key values are blocked on save; everything else (cross-table references, status vocabulary, etc.) is still validated by scripts/validate_integrity.py before merge, same as always.
